# 工作台扩展接口约定 v1

2026-10-18。配套规范：`SPEC-navigation-responsibilities.md`。

## 当前实现

`GET /api/extensions` 返回版本、检查时间、成员通道证据、扩展注册清单、契约版本、技能生命周期和知识来源策略。实现位于 `lib/extensions.js`；前端通过 `public/js/centers.js` 展示。

- `status` 表示适配能力：implemented / reserved / unavailable / unknown。
- `state` 表示当前已知状态：paused / stale / heartbeat-fresh / unknown。
- `registration` 只反映原台账登记，不作为在线证明。
- `observedAt` 与 `evidence` 记录证据时间和来源；请求时刻 `checkedAt` 不替代证据时间。
- WorkBuddy 暂停状态从本机 WorkBuddy 自动化数据库只读取得；仅查询匹配领取脚本的单一未删除任务的 status/updated_at，不读取 prompt、账户或凭据。无法读取或有多条匹配时不猜测，返回未知或独立队列心跳证据。
- 新鲜领取心跳只证明领取检查发生过，不能证明模型已运行、任务成功或桌面程序在线。
- `lastAttempt` 仅为历史执行记录，不能代替通道检测。
- 隔离数据环境不读取用户的 WorkBuddy 自动化数据库。
- EvoFlow、Multica 始终标记 reserved，本轮不外联、不部署、不加载其代码。

兼容 `POST /api/crew/sync` 返回 at、mode=ledger-only、crew。它不改 lastSync，不追加假同步事件，不启动成员。

## 内部适配契约

后续提供者须满足以下结构，完成适配和验收后才可把相应状态改为 implemented。下列 submit/cancel/publish 等是后续接口要求，本轮不提供对应写入 HTTP 路由。

### 运行通道

```text
RuntimeDescriptor {
  providerId, agentId, transport, capabilities[], status,
  registration, state, observedAt, evidence, lastAttempt
}
submit({projectRef, runId, stepId, attemptId, inputRefs, approvalRefs})
status({attemptId})
cancel({attemptId, reason})
```

提交与取消须使用唯一执行尝试 ID，区分提交不确定、领取、实际启动和完成。重试不能假定上次未执行；暂停、归档和批准条件必须在提交前及成果收编时再次校验。

### 项目与流程

```text
ProjectRef { kind: module | department-run, id }
WorkflowStep { projectRef, runId, stepId, attemptId, dependsOn[],
               inputs[], outputs[], acceptance[], approvalRefs[] }
```

当前 canonical 路由为 `#projects/mod:<id>` 与 `#projects/run:<id>`。同名或同 ID 的两类记录不自动关联。现有四岗位链是默认实现，本轮不引入新的 DAG 调度。

### 经验转技能

```text
SkillCandidate { sourceRefs[], lessonId, draftId, skillId, version,
                 reviewState, allowedAgents[], activePath, validationEvidence[] }
stages = experience -> draft -> confirmed -> published -> usage-receipt
```

候选记录、说明卡、实际技能文件、用户确认和真实调用回执是不同事实。发布须保留来源、适用范围及替换或撤回关系；跨 Agent 分发不能覆盖未确认的本地规则。本轮只展示既有说明卡，不自动挖掘会话、提炼、发布或分发。

### 知识来源

```text
KnowledgeSource { sourceId, kind, root, retrievalPolicy,
                  availability, observedAt, provenance }
provenance = { sourceRef, locator, sourceHash, sourceVersion, retrievedAt }
```

复用当前 Obsidian/VaultRAG，不建立平行索引。行程复盘始终使用 direct-latest-active、useVault=false，继续排除 VaultRAG。配置、可连接、可检索和已获得有效来源必须分别表达。

## 现有数据保持

`data/store.json` 继续为唯一业务台账；新导航不迁移、复制或改写业务项目、任务、工作链、报告、技能说明和经验正文。旧 hash 路由通过 `public/js/navigation.mjs` 转换到新入口。接口版本不代表未来适配已获安装或执行授权。
