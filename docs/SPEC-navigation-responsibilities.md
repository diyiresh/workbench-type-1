# 工作台模块职责整理与扩展边界

日期：2026-10-18。用户已确认 Confirm Development，进入实施与验收。

## 已确认背景

- WorkBuddy 自动领取由用户主动暂停，当前继续保持暂停；保留其执行成员身份。
- 技能库的核心需求是将跨 Agent 的经验、纠错和做法沉淀为经过确认的技能，而不仅是展示安装列表。
- 用户说明 VaultRAG 当前依赖手动启动 Docker 及打开 OpenAI WebUI；这是用户报告的运行依赖，本轮不改变启动方式，不将连接失败解释为资料缺失。
- 本轮先处理模块重复和责任不清，并为后续借鉴 EvoFlow、Multica 预留接口。

## 代码核对与设计参考

- public/app.js 的 home/all 与 work/all 都调用 homeAllView；deck 是任务总表、风险与任务拆解；ops 是周期报告；memory/skills 只是台账说明卡。
- server.js 的 /api/crew/sync 更新全员 lastSync，不实际检测执行成员，必须修正文案和行为。
- 普通 inbox 指令与 departmentRuns 项目执行队列存在边界，本轮明确标注，不将普通留言自动升级为可执行任务。
- EvoFlow 研究版本 1bb697f2892649559944674091ebae2b20fa9360：参考依赖、验收和技能授权的分离，以及知识资产的来源与索引状态。
- Multica 研究版本 18fa9f728a9e25f2465df2789631edb2a75442ad：参考成员与运行通道分离、执行回执、技能来源识别。
- 参考设计，不复制两项目代码或引入其运行时。EvoFlow 的 PolyForm Noncommercial、Multica 的附加许可条件应在以后实际集成前单独核对。

## 导航与职责

| 一级入口 | 唯一职责 | 本轮调整 |
|---|---|---|
| 首页（指挥舱） | 今日重点、风险、待决策与跨模块入口 | 纳入原决策台任务总表、风险与拆解；总览卡片进入对应功能页，避免重复详情 |
| 项目中心 | 浏览业务项目、协作工作链及其成果 | 统一事业部与虚拟部门入口；用“业务项目／协作任务”分区，保留各自数据身份 |
| Agent 中心 | 成员职责、待领指令、运行通道与可核实状态 | 替代舰队；分清台账启用、通道状态、心跳和实际执行 |
| 每日行程 | 时间安排、复盘及行程建议 | 保留；周期报告入口指向工作报告 |
| 简报中心 | 来源、阅读、收藏与归档 | 保留 |
| 工作报告 | 日报、周报、月报及其他周期报告 | 替代经营；今日行程只保留跳转，不再维护一份行程页面 |
| 资产中心 | 经验、教训、提示词、技能与知识的统一管理入口 | 替代记忆；本轮展示现有真实记录与已有知识连接能力，标明后续功能边界 |
| 学习 | 学习目标与计划 | 保留 |
| 生活 | 习惯与生活安排 | 保留 |
| 设置 | 偏好、连接配置、使用说明与逻辑图 | 保留；常用资料阅读入口进入资产中心，连接设置仍在设置 |

首页的风险和任务表读取同一批任务，统一风险去重及归档、暂停排除规则。页面统计数字必须能对应实际列表。

## 数据与旧入口兼容

- data/store.json 继续为唯一业务台账，正文仍在原项目或笔记目录。
- 不按名称猜测或自动合并 modules/tasks 与 departmentRuns；业务项目不等同于一次协作执行。
- 原 #deck、#work、#department、#crew、#ops、#memory 等深链接映射到新入口，保留可定位的旧记录 ID。
- 项目中心使用带类型的目标标识区分业务模块和协作工作链，防止 ID 或默认分区冲突。
- 保留全部历史、成果、归档与暂停状态；继续沿用显式恢复、写作批准、独立复核和文件交付核验。
- 更新使用说明、逻辑图和跳转文案，不批量改写用户填写的业务标题或正文。

## Agent 中心的真实状态

- “台账启用”只说明成员登记状态，不表示程序在线或能够执行。
- 运行通道状态由可追溯记录提供；未检测或过期必须显示未知、陈旧、暂停或不可连接，附来源和检查时间。
- WorkBuddy 队列心跳不等于执行成功；当前有意暂停不得只显示“离线故障”，不能自动恢复。
- 原“联系各部门”改为“刷新台账状态”，不再伪写全员 lastSync；兼容接口保留旧字段并明确本次只是读取汇总。
- 普通指令明确标注“已登记／等待成员读取”；只有实际接入执行通道的任务才能显示已领取和执行中。
- 页面打开或刷新不调用模型、不重发任务，不读取或展示凭据。

## 扩展契约（本轮预留，不启用外部系统）

采用现有 Node.js HTTP 服务、原生 ES Modules 和 CSS，不引入新框架、数据库或依赖。

建立内部扩展注册表及只读 GET /api/extensions 能力清单；项目和资产页通过适配层读取已有数据。新增写入接口本轮不开放。

| 能力 | 最小契约 | 本轮边界 |
|---|---|---|
| Agent 运行适配 | providerId、agentId、transport、capabilities、state、observedAt、evidence；后续 submit/status/cancel 方法 | 记录现有通道能力及未知项；EvoFlow、Multica 标为 reserved，不宣称已安装或连接 |
| 协作执行适配 | projectRef、runId、stepId、attemptId、dependsOn、inputs、outputs、acceptance、approvalRefs | 现有四岗位工作链作为默认模板；本轮不增加 DAG 调度或并行执行 |
| 经验转技能适配 | sourceRefs、lessonId、draftId、skillId、version、reviewState、allowedAgents、activePath、validationEvidence | 明确“经验记录→技能草稿→用户确认→发布版本→Agent 使用回执”流程；自动提炼与分发留到后续 |
| 知识来源适配 | sourceId、kind、root、retrievalPolicy、availability、observedAt、provenance | 接续已有 VaultRAG 与独立复盘笔记；不新建索引、不启动容器 |

所有能力清单区分 implemented、reserved、unavailable、unknown；注册能力不等于已检测登录或完成执行。第三方适配项不提供假成功、无效操作按钮或自动外联。

技能候选与已发布技能分开；用户一句纠错不能未经确认直接变成所有 Agent 的永久规则。保留纠错来源、适用场景和撤回或新版本替换的位置。

知识与经验分开：行程复盘继续 useVault:false，目录继续排除 VaultRAG；资产中心集中展示不改变其检索边界。

## 实施顺序

1. 路由与职责清单：统一页面归属和兼容旧深链接，避免业务数据迁移。
2. 整理首页、项目中心、工作报告与跨页面跳转，去掉重复操作入口。
3. 整理 Agent 中心的状态和刷新行为，保留所有执行暂停。
4. 整理资产中心与扩展适配契约，显示现有能力及待接入边界。
5. 同步中英文、四主题、说明与逻辑图，完成隔离环境验收。
