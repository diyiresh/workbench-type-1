## 已实现

- `lib/desktop-bridge.js` 写入唯一 `.request.json`，等待同编号 `.result.json`。
- 请求携带工作链与阶段编号；结果必须匹配 `jobId`、`agentId` 且正文非空。
- 已存在的编号拒绝再次发布；超时报告阻塞，不自动重发。
- `external-runtime.js` 支持工作链 `workbuddyTransport: "desktop-ui"`，成果仍经过原阶段检查、写作确认和群聊回写逻辑。
- 本机 automation 接口允许明确选择 `desktop-ui` 或 `cli`；没有更改其他模块。

## 当前操作边界

现在由 Codex 的 Computer Use 会话执行界面动作；不能把这种交互会话视为随工作台启动的常驻服务。未验证锁屏、电脑重启、多项目并发、权限弹窗和完整 Cursor 复核。未对业务研究报告做本轮验收。

下一步必须实现并验收独立桌面执行器：串行领取、会话绑定、发送前记录、发送后确认、超时停止、任务结果收取。发送状态不确定时人工核对，不能盲目重试。新服务模式不应在执行器就绪前批量开启。

## 可复用发送器回归

`lib/desktop-worker.mjs` 已实现由调用者提供 Computer Use SDK 的发送器。每次 tick 只执行一个界面动作；状态依次为 opening、focused、typed、transmitting、sent，成果回收后由桥接程序标为 collected。未确认发送时禁止重发，sent 或 needs_attention 会阻止新任务派入。支持调用者提供暂停信号；尚未自动识别用户正在操作电脑。

真实测试 `db-worker-20261010-a6`：发送器自动打开新任务、聚焦、输入、发送和确认，WorkBuddy 写出 29×37=1073，等待中的 Node 程序自动收到完整正文并正常退出。证据为 `data/desktop-worker-test/db-worker-20261010-a6.request.json` 与 `.result.json`。

较早 A4、A5 尝试在控件几何信息或界面时序检查处停止，没有发送成功的证据；不能计为成功，不得自动重放。逐动作实现解决了本次实测的时序问题。

`node test/desktop-worker.test.mjs` 验证单动作、发送不确定时不重复点击、串行阻塞与暂停；现有 npm test 全部通过。尚未部署正式服务，未完成 Cursor 真实复核及 Codex 最终整合，也未证明独立后台运行。下一轮应优先解决桌面执行器运行宿主，再用脱敏的小型实际项目验证全链。
