## 一、目标与边界

让用户在原有项目中心和 Agent 中心看到一项工作从正式派发到实际交付的可核实过程；让同一阶段只有一个有效执行归属，暂停后不继续推进，重试不造成无意重复执行，并让第一轮发布的技能能明确绑定到正式阶段。

继续使用当前十入口、Node.js HTTP 服务、原生 ES Modules/CSS、唯一台账 data/store.json。保留 Codex 主管/整合、WorkBuddy 执行、Cursor 独立复核四岗位默认工作链；不新增平行控制台、任务数据库或通用 Agent 框架。

WorkBuddy 的自动领取是用户主动暂停，继续保持。此次开发不修改 WorkBuddy 自动化数据库、不恢复定时任务，不以真实业务任务作测试。知识库文件可视化、VaultRAG 自动启动和复杂依赖图留在第三迭代或独立需求。

## 三、借鉴三个项目的明确落点

- Paperclip `4415665d67b16ffefbe4519c4bdd521f37bb87b9`：主要借鉴 checkout 所有权、任务与执行尝试分离、回执、独立复核及运行治理。参考 [Heartbeat Protocol](https://github.com/paperclipai/paperclip/blob/4415665d67b16ffefbe4519c4bdd521f37bb87b9/docs/guides/agent-developer/heartbeat-protocol.md)、[执行政策](https://github.com/paperclipai/paperclip/blob/4415665d67b16ffefbe4519c4bdd521f37bb87b9/docs/guides/execution-policy.md)。

本轮独立实现所需机制，不直接移植上述项目服务或 UI。继续保持前轮许可边界；不新增其运行依赖、付费 API 或凭据同步。

## 四、本轮 MVP

### 1. 项目执行时间线

在原项目房间展示：正式任务已登记、等待领取、已领取、执行器已启动/成员回报开始、等待材料、结果不确定、执行失败、成果已返回、待独立复核、待文件交付验收、最终完成。

业务阶段状态与执行尝试状态分开。进程启动只证明执行器启动，成员自报开始须注明来源；均不能单独证明模型成功或文件交付。沿用实际文件清单、源版本/哈希和独立复核结果决定最终交付状态。

旧任务与历史成果不重跑、不重建；不能从原字段证明的细分事实标“历史记录未核实”，保留原始字段和证据，不编造开始/结束时间。

### 2. 统一领取与结果收编

新增执行尝试元数据，仍在唯一台账中。现有 codexJobs/externalJobs 保留为兼容引用；新状态由同一生命周期服务提交，避免两边各自写一份进度。

拟定核心字段：attemptId、runId、stepId、agentId、transport、state、claimId、leaseOwner、leaseExpiresAt、controlGeneration、inputSnapshot、skillBindings、startedEvidence、resultHash、blockerCode、supersedesAttemptId。

- 所有新增执行先生成持久化 attemptId，使用带预期状态/输入版本/幂等键的领取事务；同阶段只允许一个有效归属。HTTP 请求体接收完后读取最新台账，再同步检查和提交，不把异步等待前的旧对象写回。
- 队列文件只是传输封装，不能独立授权执行或推进业务。与正式阶段及 attemptId/claimId 双向核对；重复领取或回报同一结果返回同一回执，冲突结果不覆盖原成果。
- 接收输入包括阶段说明、前置成果版本、执行成员、写作/交付批准及技能版本快照；变更需要新尝试，不允许用旧结果覆盖新要求。
- 暂停、归档、恢复、改派及影响执行的批准/输入变动增加控制代数。提交前、实际启动前和收编前共同校验；迟到成果完整保留，不推进接力、不自动判通过。
- 租约到期不能证明成员从未执行。存在启动或提交不确定时先进入待核对，不自动重发；锁文件也不能只按年龄直接删除。

领取凭证用于关联归属及避免意外重放，不把它宣称为本机多进程之间的完整身份认证或隔离系统。

### 3. 可解释的运行通道

Agent 中心分别显示成员登记、通道能力、最近检查时间、调度暂停、领取心跳、当前执行尝试及故障原因。页面刷新仅读取，不伪造在线时间、不启动成员、不刷新重试额度。

WorkBuddy 沿用现有桌面定时领取及脚本，不复制桌面登录凭据、不回落到已知不可用的独立 CLI。明确区分：用户暂停、等待下次定时检查、心跳过期、已领取未有开始证据、开始后结果未回报。

开发不能解除当前 WorkBuddy 暂停。无法确定调度状态时显示未知；自动执行入口不得以未知代替许可。未来用户恢复后才能做真实桌面领取验收，不能用契约替身测试冒充已恢复或已成功领取。

### 4. 正式阶段绑定已发布技能

在项目阶段编辑区选择工作台自有、已确认发布且授权给该成员的技能，保存明确版本和适用范围。发起前核对实际文件哈希；停用、缺失、被改动或成员不符时阻止启动并说明原因。

技能正文通过现有通道加入本次阶段输入，不写各 Agent 的全局技能目录。升级技能不改正在执行的输入；需要用户明确更新绑定并重新发起。

记录提示/文件传入证据，接收标记为可选的成员确认；缺少标记不能伪称已确认采用。实际采用和成果是否符合规则仍需检查输出及独立复核，不能由自报标记直接判通过。回执元数据不得混入正式报告正文。

### 5. 故障与恢复操作

稳定原因至少包括：workbuddy_paused、heartbeat_stale、runtime_unavailable、auth_required、dependency_unavailable、already_claimed、input_changed、lease_expired、result_uncertain、attempt_interrupted、result_identity_mismatch、review_budget_exhausted。代码由对应失败分支给出，页面显示中英文解释和可执行的下一步。

“核对状态”“补充材料”“重新发起一次”“继续项目”分别处理，不用一个模糊重试按钮包办。每个重试具有幂等键，关联原尝试；结果不确定时不能直接再执行。保持现有每轮最多三次真实复核退回的限制，不重置历史意见或基线。

初始默认同一 Agent 同时最多一个正式执行尝试，明确排队；技能测试和群聊也在准入时检查通道占用，避免跨入口相互抢占。保留现有通道时限并将其明确展示，不直接缩短 WorkBuddy 每小时桌面领取的等待窗口。正常执行失败不自动重试，继续由用户明确决定；复核返工仍受既有三轮上限约束。

额度页面只显示能取得的实际用量，未知不显示为 0；本期控制并发、时长、重复尝试和复核轮次，不承诺读取腾讯订阅剩余额度。

### 6. 普通留言转为正式任务

保留 inbox 的“普通指令/留言”身份。增加显式转任务预览：选择关联项目或新建协作任务、负责人、输入、交付物和验收要求。确认后才建立一次可执行任务关联，重复确认不会复制任务；原留言和转换回执保留。

转换不自动获得 Start Writing、不解除暂停，也不擅自把业务模块按同名绑定到协作工作链。

## 五、实施顺序与改动位置

1. 先固化两个已复现的暂停回归：统一控制代数与准入/收编策略，覆盖 Codex、外部执行、桌面队列、群聊的边界。群聊讨论本身不推进业务，但不得绕过通道暂停或业务批准。
2. 建立执行尝试/幂等/领取凭证与队列适配，接入既有任务、job 和结果文件；兼容旧协议的读取，旧协议写入必须通过兼容适配校验，不能成为绕过门禁的后门。
3. 增加项目时间线、Agent 通道/阻塞原因和明确恢复操作；延续中英文、四主题、窄屏和旧链接。
4. 接入已发布技能的阶段绑定与回执，完成普通留言转任务预览。
5. 隔离台账回归、可用通道的无业务资料验证和运行边界复核；更新说明与逻辑图，在既有开发分支本地提交。

预计主要改动：新增执行策略与尝试生命周期模块；调整 agent-dispatch、workbuddy-queue、desktop-bridge、codex-jobs、external-runtime、project-chat、skill-studio、department、server API；在项目/Agent 页追加展示与操作。不整体重写这些系统。

## 六、验收标准

- 两个已复现暂停问题由失败用例转为通过：暂停时拒绝领取；执行中暂停及暂停后又恢复，旧结果均留存而不解锁后续阶段。
- 并发领取只有一个有效归属；响应丢失后同键重试不新建执行；身份/版本/代数冲突不能覆盖已有状态。
- 队列已领取而台账确认失败、进程启动失败、结果迟到/重复/错配、服务重启和租约过期均有确定状态及下一步，不盲目自动重发。
- 等待 WorkBuddy 领取不能显示成已实际执行；用户暂停、心跳过期和认证失败可以区分。
- 一个 Agent 跨项目/群聊/技能测试的准入不会超出既定并发上限；超时与复核上限持久化，重启不刷新。
- 绑定技能精确到已确认版本与实际哈希；更换成员或篡改技能会阻止启动；测试回执不冒充正式阶段使用，成员自报不代替独立复核。
- 普通留言不会自行执行；转换预览/确认具备幂等与暂停、写作批准约束。
- 验收实际文件、主执行人与复核人分离、归档恢复后明确继续、行程复盘 useVault:false 等既有规则无回归。
- 页面首次进入、刷新、往返导航无自动领取、模型调用或重试，草稿不被状态刷新覆盖；中英文、四主题、窄屏可用。
- 保留所有现有业务历史与暂停状态，不在生产台账建立验收项目。WorkBuddy 真实领取状态记为“当前暂停，待用户恢复后验证”；其他通道的真实成功或实际阻塞单独报告，不把模拟执行写成真调用。

VaultRAG 当前连接问题不在本轮自动修复范围。正式任务需要知识检索时按原有政策执行；依赖不可用须显示实际阻塞，不静默关闭知识检索来换取成功。合成通道测试可使用独立测试配置，不能改生产连接设置。
