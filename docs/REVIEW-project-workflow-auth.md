# 新流程批准身份修复记录

日期：2026-11-25（Asia/Shanghai）。状态：工作区实现和隔离测试完成，尚未部署、尚未独立复核。项目负责人：Codex（董事长本聊天明确任命）。

## 取舍与范围

保留本机 Node 服务和唯一业务台账。首期收敛到一个项目、一个节点、一个实际 Word 文件的闭环；Grok 接入不阻塞该闭环。不把全部评审建议视作董事长已批准的命令，不改变 main 单线约定。

H1 成立。本机地址和 `confirmed:true` 不是批准人身份。仅从普通网页领取 Cookie 的方案不足以区别浏览器和其他本机 HTTP 客户端，因此未采用。新增独立操作口令：HTTP 不提供注册、读取或重置接口；页面需要时使用密码框，每次敏感操作认证，不放入 localStorage、项目消息或幂等业务回执。

口令校验文件为当前数据目录下 `chairman-auth.json`，仅保存随机盐及 scrypt 派生值，不进入 `store.json`，不通过状态接口返回。支持中文口令；错误尝试受限。未配置时敏感操作明确拒绝，不默认放行。

保护范围包括新流程的创建、任命、开始组织方案、方案批准/修订、暂停/恢复、启动协助确认及最终验收；同时保护新流程的旧控制/核对/技能入口，以及含有新流程记录时的整库替换和重置，避免从通用写接口绕过。

这是 HTTP 身份边界，不是同一 Windows 用户下的进程隔离。能够直接改写程序、凭据校验文件或台账的进程仍在此边界之外。不能宣称所有本机 Agent 都已被操作系统隔离。

首次真实试点前，由董事长本人在本机终端执行：

```text
node scripts/chairman-auth.cjs setup
```

脚本只接受交互终端输入，隐藏输入并要求重复确认；已有校验文件时拒绝覆盖。实施 Agent 不代设口令，不要求董事长把口令发进聊天。此项属于批准身份初始化，不是把普通技术排障转给董事长。
