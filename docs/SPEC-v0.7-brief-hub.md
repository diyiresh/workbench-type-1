# SPEC v0.7：跨 Agent 简报中心

## 目标

在不复制 ChatGPT、WorkBuddy 各自调度系统的前提下，让本机工作台成为所有定时简报的唯一阅读入口：外部 Agent 继续负责生成，工作台负责收件、去重、状态监测、开屏呈现和历史留存。

## 数据边界

1. `briefSources` 保存来源名称、平台、原调度说明与期望到达周期，不保存第三方账号密码或 Token。
2. `briefRuns` 保存每次已完成简报的正文、来源、完成时间、原始链接或本机文件路径以及已读状态。
3. 外部原文不得被工作台自动改写；开屏只展示摘录，简报中心保留完整正文。
4. 相同来源的同一 `externalRunId` 只能入库一次；没有外部运行 ID 时使用内容指纹去重。
5. 默认 HTTP 投递只接受本机回环地址。不会调用 HTTP 的 Agent 使用 `data/dropbox/` JSON 文件报送。

## 首批来源

- ChatGPT · Daily Priority Briefing（每日 08:00）
- ChatGPT · Guangdong Construction Brief（每周一 08:00）
- ChatGPT · Practical AI Research（每周五 18:00）
- WorkBuddy · 每日 AI 新闻推送（具体时间沿用 WorkBuddy 当前设置）

## 交互

1. 左侧新增“简”一级栏目，二级目录按来源过滤。
2. 总览显示来源数、今日到件、未读数和需要关注的来源数。
3. 每条简报可展开全文、标记已读，并显示原始链接或路径（只展示，不自动打开外部未知链接）。
4. 开屏简报增加“跨 Agent 简报”一页，汇总各来源的最新到件摘录。
5. 设置页展示统一投递方式和本地 dropbox 路径。

## 接入策略

### ChatGPT

把现有计划任务设置为本地项目任务，项目目录选择本工作台；生成完成后写入 `data/dropbox/*.json`。如果工作台服务正在运行，也可 POST 到 `http://127.0.0.1:3780/api/brief-runs`。

### WorkBuddy

首选在现有“每日 AI 新闻推送”任务末尾增加同样的 JSON 落盘步骤。若其计划任务不能访问 Windows 本地目录，再单独启用 WorkBuddy OAuth 2.1 / Open API 拉取适配器；OAuth 不属于本期 MVP。

## 验收清单

- [ ] 四个默认来源迁移后存在，且不覆盖已有台账。
- [ ] HTTP 与 dropbox 两种方式均可写入简报。
- [ ] 重复 `externalRunId` 或相同内容不会重复入库。
- [ ] 简报中心可按来源查看全文并标记已读。
- [ ] 日更来源超出期望周期后显示“迟到”，周更来源使用独立周期。
- [ ] 开屏出现跨 Agent 最新简报摘录，完整原文仍在简报中心。
- [ ] 现有主题、日程、学习、生活、报告及测试继续通过。
