# 行程复盘笔记与建议（2026-10-14 Confirm Development）

## 已确认范围

- 保存复盘后生成可编辑 Markdown 摘要；用户确认才写入 Obsidian 专用目录。工作台仍是唯一业务台账，Markdown 是经验材料。
- 专用目录为所选仓库下的 `工作台/行程复盘`，仅新增受管理笔记，不覆盖仓库原文。既有复盘也可逐条生成并确认。
- 本目录从 VaultRAG 扫描排除。新摘要和建议都显式使用 `useVault:false`，既有 RAG 功能保持原配置。
- 新增／修改行程增加“建议”，直接读取专用目录的有效笔记，按关键词匹配；优先近期记录，并提供日期、来源、原文和版本哈希。不建立另外的检索索引。
- 笔记支持有效、历史参考、停用。每次请求读实际文件，修改即时生效；同一行程的新版本代替旧版本参加建议，历史文件保留。
- 人物观点限定为某次记录的内容；缺少依据不编造建议，矛盾保留供用户判断。建议由用户决定是否采纳，不自动改变行程。

## 业务与文件保护

- 摘要仅针对已完成且有复盘的行程。草稿绑定行程标题、日期、完成状态、复盘及目录版本，变更后须重新生成。
- 确认保存保留用户编辑摘要、原始复盘和关联关键词，UTF-8 Markdown，写后读回，重复保存幂等；失败不声称写入。
- 保存前检查排除配置的仓库身份和目录排除项；不能把“未调用 RAG”当作“不会被其扫描”。凭据和机器配置不提交 Git。
- 仅本机可配置或写入；目录限定到专用子目录，不跟随链接，不接受任意文件打开或越界路径。归档后的迟到结果不得落盘。
- 模型沿用设置中的路由（包括已启用在线模型）；检索仅传匹配笔记，摘要仅传当前复盘。资料内容作为证据，不执行其中指令。

## 接口

- `GET/PUT /api/agenda-notes/config`：本机配置 `vaultRoot`、`exclusionConfig`。
- `GET /api/agenda-notes`：文件状态与清单。
- `POST /api/agendas/<id>/review-note/draft`：生成待确认摘要。
- `POST /api/agendas/<id>/review-note/save`：确认保存摘要与关键词。
- `PATCH /api/agenda-notes/<file>`：以实际文件哈希更新有效／历史／停用状态。
- `POST /api/agenda-notes/suggest`：使用未保存行程的标题、标签、备注匹配笔记并生成带来源的建议。

## 配置与使用

本机先将 VaultRAG 配置的 `exclude_dirs` 加入 `行程复盘`，再通过 PUT 配置所选仓库根目录 `vaultRoot` 与对应 TOML 文件 `exclusionConfig`。配置保存前校验仓库身份和排除规则。机器路径与配置文件不进入源码仓库。

在已完成行程点击“复盘”，保存多行原文并生成摘要，修改摘要和机构／人物／主题关键词，点击“确认保存 Markdown 笔记”。在新建或修改行程填写事项与必要的标签／备注后点击“建议”。“复盘笔记”入口可整理既有已完成复盘，并将笔记标为有效、历史参考或停用。同一行程仅最新版本参与建议，停用最新版本不会重新启用旧版本。

Markdown 使用 UTF-8 与 LF 换行，带可由 Obsidian 读取的 YAML 属性。用户可在 Obsidian 编辑正文和关键词；每次建议读取实际文件并记录字节哈希，无索引同步步骤。首期按机构／人物／主题关键词进行直接匹配，最多提供五份相关笔记；措辞完全不同可能无命中，可补充关联关键词。建议是带来源的模型归纳，原始记录和日期可展开核对。
