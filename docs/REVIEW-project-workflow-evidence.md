# 角色验证与审核证据修订记录

2026-11-25，Asia/Shanghai。负责人：Codex。状态：隔离验证完成；真实成员试点和独立复核尚未完成，不作为用户验收。

## 本轮修订

1. 每个新项目先为所选三角色创建受执行治理约束的通道验证单元。验证只使用随机生成的公开虚构材料，不发送业务目标和材料。负责人验证结构化方案，执行人验证完整结果，审核人验证读回文本和结构化结论。字段中的成员身份来自实际尝试，不相信模型自报身份。
2. 验证记录绑定项目、角色、成员、实际尝试、结果哈希及通道配置指纹，有效期四小时。指纹包含执行适配器源码、已知模型/地址配置、传输模式及成员控制代数。每次派发重新核对；过期或已知配置变更先验证再执行。通道配置在调用中改变时，结果保留 held，不推进。未报告的上游模型变化仍可能无法即时检测，实际调用失败继续受原治理约束。
3. 自动通道能力验证不能由人工回填替代；每角色的验证尝试仍有累计预算，不因新时间戳或新工作单元无限重开。验证失败不偷偷换成员。
4. 节点方案增加验收条目列表，原单条验收文字保持兼容。审核返回严格 JSON，每条批准标准须有独立结论、位置、理由和执行正文摘录。通过时所有条目都须通过，缺项拒绝。单独出现 VERDICT 或 FILE_REVIEW 不再提供批准依据。
5. 文件审核通过还须逐份提供实际文件 ID、哈希和读回文本摘录。后台校验实际文件批次/快照、当前文件及读回材料，摘录不匹配则拒绝。审核记录绑定派发时冻结的执行结果哈希，不从“当前结果”补写一个恒真的匹配值。
6. 页面按需读取历史长正文；审核依据按验收条目呈现，保留原始工作单元供追溯。未初始化批准口令时，新建失败的原因在表单内显示，保留已有草稿。

这些校验只证明协议、来源绑定和证据一致性，不证明模型的判断一定正确。部分成员接收后台从实际文件读取的文本，记录为 provided-readback；不能称其自行打开了 Word，也不能称其已做视觉/版式检查。当前一期试点应验证公开清单的内容交付，不扩大为复杂排版能力验收。
