# 统筹工作台 v0.8：虚拟部门

## 目标

在不改变现有紫色指挥舱、暖白和深色主题视觉体系的前提下，把“给某个 Agent 单独下任务”的工作台升级为一个可追踪的虚拟部门：董事长只需提出一个目标，系统负责形成计划、安排执行、独立复核、退回返工和最终汇总。

## 本期范围（纵向 MVP）

1. 固定四个岗位：部门主管、主执行人、独立复核人、整合秘书。
2. 岗位固定，实际承办引擎按能力动态选择；模型不可用时保留规则计划并明确标注，不伪装成已由 AI 执行。
3. 一个目标形成一条完整工作链：`计划 → 执行 → 独立复核 → 汇总`。
4. 每一阶段只在前置阶段完成后才能启动；主执行人不得复核自己的成果。
5. 复核不通过时，主执行阶段进入返工，保留退回意见和历史成果。
6. 共享目标、阶段成果、讨论记录和材料路径均写入同一本机台账。
7. 支持当前模型路由（本地 Ollama 或在线 OpenAI 兼容接口）执行计划、产出、复核和汇总。
   用户明确点击“一键自动接力”后，可连续推进低风险文字阶段；在线接口调用前必须提示可能产生费用。
8. 删除、外发、付费调用、系统级写入等高风险动作不在本期自动执行；只记录为“待董事长批准”。
9. 保留既有日程、学习、生活、简报、经营、舰队、记忆和设置模块，不迁移、不改名、不换配色。

## 数据结构

- `departments[]`：部门定义、岗位策略和默认审批策略。
- `departmentRuns[]`：用户目标、当前状态、四阶段工作项、讨论、成果、审批和最终摘要。
- `departmentRuns[].items[]`：岗位、承办 Agent、执行引擎、依赖、状态、输入、输出、材料和复核结论。

## 状态约束

- 工作项：`blocked → queued → doing → review → done`；被复核退回时为 `rework`。
- 运行：`planning → active → rework → completed`。
- 只有依赖项全部 `done`，下一项才可从 `blocked` 进入 `queued`。
- `reviewerAgentId` 必须与被复核工作项的 `ownerAgentId` 不同。
- 只有复核通过，整合秘书才能开始；只有整合秘书完成，整条运行才能完成。

## 真实能力边界

- 当前模型路由：可真实调用，用于四阶段的文字推理和产出。
- Cursor、Codex、WorkBuddy、ChatGPT 页面任务：本期作为可选择承办方和交接对象展示；若没有受支持的机器接口，不声称已经自动唤醒。
- 工作台会明确显示“模型执行”“人工/外部 Agent 回填”或“规则计划”，避免把页面占位当作真实接入。

## UI 锁定

- 沿用 `styles.css` 的现有主题变量：`--paper`、`--canvas`、`--accent`、`--accent-deep`、`--hero-a`、`--hero-b` 等。
- 新页面继续使用现有 `command-hero`、`overview-stats`、`card`、`msg`、`chip`、`solid`、`ghost` 组件语汇。
- 不引入 Paperclip 的黑白视觉皮肤；只借鉴其组织、任务、审批、审计和成果链路。

## 验收清单

- [ ] 输入一个目标后生成四岗位工作链。
- [ ] 前置依赖未完成时，后续阶段不能启动。
- [ ] 主执行人不能成为该成果的复核人。
- [ ] 复核退回后主执行项进入返工，并保留意见。
- [ ] 复核通过后可生成最终整合稿，运行状态变为完成。
- [ ] 模型不可用时给出明确错误或规则降级，不丢失目标。
- [ ] 长文本目标在页面切换后仍保留草稿。
- [ ] 三套现有主题下新页面均可读，原有模块回归测试全部通过。
