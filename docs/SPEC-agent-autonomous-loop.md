# 自动部门接力验收规范

## 目标与边界
用户在虚拟部门建项目、选成员、提交目标并启动一次；Codex 拆解，WorkBuddy 执行，Cursor 独立复核，Codex 整合。所有阶段及成果回到工作台唯一台账，其他模块不变。研究报告完整写作仍须 Start Writing；单功能验收任务可直接执行。

## 技术路线
保留真实 Codex CLI 和 Cursor CLI。WorkBuddy 使用官方桌面自动化主动领取本机队列，绕开已实测失败的独立 CLI 登录；不提取或复制桌面凭据，不伪装客户端。当前桌面版持久间隔最低一小时，因此页面须明确等待时间。Computer Use 发消息路径保留作本轮即时验证工具，不宣称常驻。

队列串行领取，结果按任务编号校验；在领取前记录状态，失败或发送结果不确定不自动重放。原件由用户人工脱敏。共享 skills、memory、context 使用 Ben_My_Agent，成果写在各项目目录或工作台阶段成果区。

## 本轮验收
1. WorkBuddy 自动化配置持久保存，真实领取独立验收任务并写回，空队列返回空闲。
2. Codex、WorkBuddy、Cursor、Codex 四阶段均为真实调用，最终全文可读回；不手工伪造成员成果。
3. 新项目默认岗位匹配上述分工，整合自动启动；失败展示实际原因而非假完成。
4. 串行、多次领取、身份不匹配、服务重启和返工有回归测试；已有测试通过。
5. 报告修订项目先阅读材料与提出纲要，未经写作确认不自动完成正文。

## 显式重试的有界返工（2026-10-11故障修复）

每轮最多三次真实审核退回；启动失败和登录重试不计入。历史项目未记录恢复基线时仍按原有累计三次暂停。只有项目已暂停且本轮审核额度耗尽时，现有 automation 接口的显式 `retry:true` 才记录新的退回基线，保留历史意见，并允许后续新增三次退回。普通启用、重复重试、运行中失败重试、群聊和服务重启均不刷新审核额度；`enabled:false` 不恢复暂停。恢复记录保存在同一项目的 `automationRecoveries`，项目房间保存系统回执。

验收覆盖：三条旧退回后的显式恢复、历史不变、重复请求不增加额度、持久化重建后计数一致、真实状态机新增三次退回再次暂停、暂停期间无重复 blocker 或调用。测试执行器使用替身，不代表报告业务验收。本次部署不恢复 dr-vruuszla5e 的业务暂停。
