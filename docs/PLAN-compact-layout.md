# 界面精简：导航等长、二级栏收起、阶段说明展开

2026-10-18。状态：用户 Confirm Development 后已实施，验收见 SPEC-compact-layout.md。

## 需求与已核对位置

用户第一张截图的区域 1 为一级导航，区域 2 为含工作台名称、搜索及模块列表的二级栏。第二张截图为四角色接力中的阶段说明。

已核对：`public/js/navigation.mjs`、`public/app.js` 的 rail/render、`public/index.html`、`public/styles.css`、`public/js/views.js` 的 departmentItemCard。目前导航混用二字、四字及英文名称；宽屏三列布局的二级栏没有常驻切换按钮；阶段 instruction 直接完整输出，长历史上下文导致卡片过高。

## 建议方案

### 1. 一级导航

中文统一为四字：工作首页、项目中心、成员中心、每日行程、简报中心、工作报告、资产中心、学习成长、生活管理、系统设置。

首页 → 工作首页；Agent 中心 → 成员中心；学习 → 学习成长；生活 → 生活管理；设置 → 系统设置。其余名称保持。名称在导航、页面标题与说明入口中一致；原路由 ID 与旧链接仍定位原功能，用户业务标题和正文保持原文。英文使用自然译名，并通过相同宽高及对齐形成整齐排列，不靠补空格或截断文字。

### 2. 二级栏切换

在工作区顶栏左侧增加始终可见的“收起侧栏 / 展开侧栏”按钮。收起区域 2 后释放其占用空间，区域 1 仍可切换一级页面；再次点击恢复工作台名称、搜索及二级列表。首次宽屏进入默认展开，本浏览器记住用户选择；窄屏用同一按钮打开/关闭抽屉，遮罩和 Escape 可关闭。

切换只改变界面布局，不重建当前业务表单；保留已输入的消息、行程和其他草稿。按钮具有可访问名称、展开状态及键盘操作，收起状态下焦点不会落入隐藏区域。窄屏抽屉与宽屏偏好分开，避免窗口缩放导致全局导航失去入口。

### 3. 四角色阶段说明

四个角色统一处理 instruction：默认最多显示四行预览，内容过长时在预览下显示“展开详情”，展开后显示完整原文并可“收起详情”；短说明不出现多余按钮。状态、负责人、执行操作和既有“查看阶段成果”保持独立可用。

全文始终保留在原台账，不通过截断保存来压缩。页面内部的状态刷新保留已展开选择，首次进入项目默认收起；更换项目时按各阶段身份区分。兼容纯英文、长中文、换行、长路径和无空格字符串。

## 参考、技术与风险

参考 shadcn/ui 的 SidebarTrigger 常驻开关、桌面侧栏释放宽度及移动端抽屉分离的交互设计：[源代码](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/ui/sidebar.tsx)。仅借鉴交互；使用本项目现有原生 JavaScript/CSS，不引入 React、组件库或服务依赖。

主要风险是隐藏后没有恢复入口、窄屏出现双重侧栏规则、长内容或译文溢出、自动刷新覆盖展开状态，以及仅改导航后其他页面文案失配。通过常驻顶栏按钮、明确宽窄屏状态、真实溢出判断和统一显示名称处理。
