## 需求与现状

1. 第一张截图红框是协作项目入口及其“…”操作菜单，菜单依次为置顶、重命名、归档、删除。项目标题取自台账，过长时省略显示。`public/js/views.js` 的 projectMenu 生成四项操作。
2. 已定位样式冲突：`public/styles.css` 的 `.project-menu > div` 使用 `var(--card, #fffdf8)` 浅色背景，按钮却 `color:inherit`，在紫色或中国风侧栏内继承浅色文字，形成浅底浅字。修复属于展示层，保留原操作与确认流程。
3. 第二张截图需要调整二级栏的横向宽度，在侧栏与工作区的边界拖动。当前宽屏为固定 258px／216px，`compact-layout.js` 仅处理收起与抽屉，没有调宽入口。

## 第一阶段：项目菜单

- 菜单背景、文字、边框、悬停和键盘焦点使用配套的主题变量；四主题都清晰可读。
- 保留现有置顶、重命名、归档、删除语义及确认流程；此次不触发任何管理操作。
- 检查窄侧栏、底部项目与滚动场景，避免菜单被裁切或超出可见区域。

## 第二阶段：二级栏调宽

- 在二级栏右边界加入窄拖动区；悬停或拖动时显示细高亮线和左右调整光标，不增加常驻说明文字。
- 鼠标或触控笔拖动时实时调整宽度，工作区同步缩放。桌面建议范围约 200–420px，随可用窗口宽度收紧上限，保证主区仍可使用；未保存偏好时沿用当前响应式默认宽度。
- 拖动结束后将宽度保存在本浏览器；切页、刷新、侧栏收起后再展开继续沿用。存储不可用时内存回退；不写入业务台账。
- 分隔条可键盘聚焦，以左右箭头调整；双击恢复响应式默认宽度。提供 separator 角色、可访问名称、方向与数值信息。
- 保留顶部纯图标收起开关；收起时不显示分隔条。720px 及以下继续使用抽屉，不启用桌面拖动。
- 拖动不重建表单，保留消息、搜索及未提交草稿；处理指针取消、窗口缩放和拖动中收起，清除临时光标／选中状态。

## 验收与边界

检查拖动、键盘、双击恢复、宽度边界、刷新／切页记忆、收起恢复、窗口缩放、窄屏抽屉；验证现有草稿 DOM 与输入保留。四主题、中英文核对菜单颜色与焦点，并检查实际页面。查看、调宽和打开菜单不产生业务写请求，不调用 Agent 或模型。

风险集中在可用空间不足、菜单裁切、拖动取消后遗留状态、隐藏侧栏时错误记忆宽度，以及颜色继承冲突。通过动态宽度边界、可见区域检查、统一结束清理及主题成对变量处理。
