# SPEC v0.6：生活 / 学习双星系

## 目标

在不复制日程、不污染既有 `agendas` 台账的前提下，形成生活与学习两条可执行战线：

- **繁星**：`agendas` 中分类为“生活”或“学习”的零散日程的只读引用；完成、复盘和材料仍写回原日程。
- **银河**：独立于 `agendas` 的体系化内容。生活为 12 套习惯的周期性执行记录；学习为经用户采纳的 AI 学习计划。

## 数据边界

1. `agendas` 是“日 → 繁星”的唯一来源，繁星不得复制或另存 `done`、`review`、`materials`。
2. `lifeSystem.habitRuns` 仅保存某日某习惯的执行状态；它们永不进入“每日行程”。
3. `lifeSystem.learningPlans` 保存用户已采纳的学习计划。计划的具体 sessions 全部完成后，删除 sessions，只保留一条完成成就与完成时间。
4. 所有数据只写入本机 `data/store.json`；模型密钥继续只保存在本机，不能通过 API 回传。

## 12 套习惯的默认频率

- 每日：1 早起、2 深度专注、3 早计划+晚复盘、4 深度阅读、6 第二大脑、7 拆今日动作、9 感恩、10 费曼输出、11 独立思维。
- 每周一/三/五：5 锻炼（每周 3 次为默认，允许在后续版本调整）。
- 周日：8 拒绝清单、12 一种难事。

首次打开当天的“生活”页时，以及服务端读取新日期时，系统幂等生成当天到期习惯：同一日期、同一习惯最多一条执行记录。

## 学习计划流程

1. 用户填写目标、学习内容、可投入时段、截止日期和单次时长。
2. 当前模型路由生成 JSON 候选计划。提示词必须声明：本地模型不联网，不能把内容称为最新资料或事实。
3. 服务端校验日期范围、时长、数量和字段；前端仅展示候选，不能自动写入计划。
4. 用户点击“采纳到银河”后才持久化。每个 sessions 可单独完成；全数完成后转为一条“已完成对《…》的学习，你真棒！”成就记录。

## 模型与安全

- v0.6 调用现有模型路由，默认本地 Ollama；可由设置改为 OpenAI 兼容接口。
- 不直接驱动 ChatGPT 桌面客户端、Cursor 或 WorkBuddy；未来邮箱/中转集成为独立迭代。
- 输入给模型的只有用户在学习表单中明确提交的内容及时间约束；生成计划不自动发送给任何外部服务。

## 验收清单

1. 日程分类为生活/学习后，在相应繁星区出现；任一页切换完成，另一页立即反映。
2. 当天生活银河按频率出现 9 项每日习惯，周一/三/五额外含锻炼，周日额外含两项周习惯；刷新不重复。
3. 银河习惯不出现在“每日行程”。
4. 无法在未点击采纳时写入学习计划；采纳后可逐条完成，最后一条完成后不再显示具体 sessions。
5. Ollama 未启用/不可达时，学习页给出可理解的失败提示，且不写入计划。
