# 从已保存复盘摘要生成月报

2026-10-31 用户 Confirm Development。新增独立入口，原行程周期报告保持可用；GitHub 推送仍待本地验收。

- 月视图底部增加“从复盘摘要生成月报”，先显示来源清单再确认派发。单选 Codex / Cursor / WorkBuddy，继续使用原成员通道、占用和三次尝试预算；不调用 SiliconFlow、VaultRAG 或全库检索。
- 仅读取配置仓库的 `工作台/行程复盘`。按笔记记录的行程日期筛选月份，每个 agendaId 只取最高版本且 active 的摘要；最高版本停用时不回落到旧版。排除已归档行程，缺少原行程时标注背景缺失。格式异常、缺摘要、历史或停用均有预览统计。
- 摘要优先，关联行程标题和勾选状态仅补充背景；不根据计划、勾选或文件数量虚构实际成果。生成前预览文件名、版本、保存时间、日期及 SHA-256；没有可用摘要时不派发。
- previewSnapshot 绑定实际文件内容、版本、目录配置和背景状态；启动时再次校验，执行期间及保存前继续校验。来源增删改均使旧结果 held；可按原流程明确另存历史草稿，不自动重发、不覆盖编辑。
- 任务使用 agendaReportJobs 中 sourceMode=saved-reviews，周期仍为 month；与行程报告、单项复盘任务区分。不得在旧入口误恢复摘要月报。
- 草稿可编辑；确认后仍保存到报告库与 `monthly report comes from workbench`。导出文件和台账记录 source_mode、来源文件版本及哈希，不改原复盘笔记。
- 草稿生成或显式恢复后自动定位到报告编辑区。“查看报告草稿”仅滚动定位，不覆盖编辑、不要求替换确认；“恢复原始生成稿”才明确确认替换。生成完成后提示尚未保存，保存动作仍由用户在草稿下方明确执行。
- 避免不完整生成：超大底稿明确报错，不截断或静默遗漏；恢复与刷新只读，不重新派发。

技术复用：现有 Node / ES Modules、agenda-notes 文件校验、Codex 官方完成/失败事件设计及现有月报导出，不引入依赖或第二台账。

验收：仅当前月/最高有效版本、缺失/停用/异常文件和空月；预览到派发之间变更；三个成员、原始摘要完整传递、幂等、占用和晚到结果；文件修改/新增/删除使结果过期；人工编辑后版本保存及来源留痕；原行程报告不受影响，CN/EN/窄屏。
