## ChatGPT 计划任务

将现有计划任务的执行环境改为本地项目，并选择：

`D:\OneDrive\Desktop\Ben_My_Agent\5.cursor\搭建工作台`

在每个任务原提示词末尾增加以下交付规则，并将 `sourceId` 替换成对应值：

> 完成简报后，必须把完整原文报送到当前项目的本机台账。读取项目根目录 AGENTS.md 的“报送定时简报”格式，使用 sourceId `<对应 sourceId>`、agentId `chatgpt`。优先 POST 到 `http://127.0.0.1:3780/api/brief-runs`；如果服务不可用，则把同一 JSON 安全写入 `data/dropbox/`，文件名必须带 sourceId 和本次时间，不得覆盖旧文件。externalRunId 使用本次计划运行的唯一标识；没有平台运行 ID 时使用 `YYYY-MM-DD-HHmm`。正文必须是本次简报完整原文，不能只写摘要。JSON 必须通过程序序列化，不能手工拼接转义。

本地任务需要电脑开机且 ChatGPT 桌面端正在运行。第一次修改后先手动“Run now”验证，再等正式周期。

## WorkBuddy 计划任务

在“每日 AI 新闻推送”原提示词末尾增加：

> 完成并保存每日 AI 新闻后，再向 `D:\OneDrive\Desktop\Ben_My_Agent\5.cursor\搭建工作台\data\dropbox\` 写入一份 JSON 回执。格式读取该目录项目 AGENTS.md 的“报送定时简报”，kind 为 `brief`，sourceId 为 `workbuddy-ai-news`，agentId 为 `workbuddy`，externalRunId 使用本次运行日期时间，body 保存完整简报正文。新建文件，不得覆盖历史文件；JSON 必须通过程序序列化。

如果 WorkBuddy 定时任务提示无权访问该 Windows 路径，停止反复尝试。该情况需要进入下一阶段，通过 WorkBuddy OAuth 2.1 与 Open API 拉取消息或任务产物。

## 本机 HTTP 示例

```powershell
$payload = @{
  sourceId = "chatgpt-daily-priority"
  externalRunId = "2026-09-27-0800"
  agentId = "chatgpt"
  title = "Daily Priority Briefing"
  completedAt = "2026-09-27T08:00:00+08:00"
  body = "完整简报正文"
} | ConvertTo-Json

Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:3780/api/brief-runs" -ContentType "application/json" -Body $payload
```

同一 `externalRunId` 重复提交不会生成第二份简报。
