# Workbench V9 — 履职成长

用户于2026-11-09授权将已确认的副站长管理能力提升与造价业务学习方案加入V9并开始开发。本规范是本轮实施与验收清单。基线为本地V8预览34e9cc7；开发分支codex/v9-professional-growth。本轮不宣称完成此前未完成的全部V8视觉改造。

## 已确认目标与范围

- 用户有工程或建设管理经验，需系统补齐造价业务；每周可投入5小时以上；具体分管范围未知。
- 学习成长增加“履职成长 V9”：八周主题、每周300分钟基础节奏、管理与专业双线实践。
- 五类卡片：重点事项、概念与文件、案例分析、管理复盘、每周一页纸。卡片可引用现有任务或行程，不复制其进度。
- 学习活动完成与理解程度分开；理解分待学习、能解释、能分析、经复核可复用。高等级需证据，复核需姓名和意见；改动后旧复核失效，历史保留。
- 官方资料入口、可复制教学指令、按实际记录生成可编辑周总结草稿。

## 技术、复用与风险

继续使用原生ES模块、Node HTTP服务、现有CSS语义变量与本地store.json，不增加运行依赖。V9计划存入lifeSystem.learningPlans，标记program为cost-management-v9；卡片存入lifeSystem.growthCards。仅在用户采纳和保存后写入，无打开即导入。既有日程、任务、知识检索、Agent通道、WorkBuddy调度、模型路由和外部工具配置不改变。

公开开源调研：
- [Anki官方README](https://github.com/ankitects/anki/blob/main/README.md)：明确为间隔重复工具。本轮参考持续复习思路，采用人工自测和复核记录；不引入记忆算法，不将重复次数当作掌握程度。
- [OpenProject官方README](https://github.com/opf/openproject/blob/dev/README.md)：任务、计划、会议与协作集中管理。本轮将成长卡关联既有事项；不另建任务进度表。
- 两项目均只参考产品组织方式，不复制实现、图标或样式。引入它们的完整架构会增加维护成本，且其许可证和部署要求需单独评估。

## 数据与接口约定

- GET /api/growth 返回公开预设、当前V9计划、成长卡与可引用事项的最小摘要，不返回模型配置和密钥。
- POST /api/growth/activate 显式采纳；校验开始日期；一个有效V9计划；重复调用返回既有计划，归档计划不自动恢复。八周各五项，共40项；日期相对开始日，不向agendas写副本。
- PATCH /api/growth/sessions/:id 修改V9计划的学习勾选；严格布尔值与预期计划修订，保存所有分次记录；已完成计划可以取消勾选重新打开。
- POST /api/growth/cards、PATCH /api/growth/cards/:id 保存卡片，校验类型、长度、出处链接、关联对象和预期修订。创建使用请求键防止重复提交。软归档可恢复，禁止物理删除。
- 周总结仅依据本周实际勾选和卡片生成草稿，明确勾选安排时长与自评的含义；生成草稿不持久化、不调用模型。
- GET只读，无启动Agent、导入资料、调用Vault或定时执行。V9写操作只允许本机且拒绝跨源请求。
- 所有用户文本转义；外链仅http/https；编辑草稿只保留当前浏览器会话，切页/刷新可恢复；保存成功才清除。并发修订冲突保留草稿并提示重新载入。
