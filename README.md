# 工作台类型 1（Type 1）

这是个人本机 Agent 工作台的**第一型 / 基线**。GitHub 仓库名为 `workbench-type-1`。正在运行的程序仍叫「统筹工作台」；本机目录和地址 `http://127.0.0.1:3780` 不因仓库名而改变。

Type 1 维护**一份本机台账**。Cursor、Codex、WorkBuddy 以及其他 Agent 都读、写这一份进度，不另建平行进度表。台账包含虚拟部门工作链（主管 → 执行 → 独立复核 → 整合）、打卡（checkpoint）、指令（inbox）和项目群聊。接入约定见 [AGENTS.md](AGENTS.md)。

程序入口是 `server.js`：`node server.js`，或双击 `start.bat`。

# 统筹工作台 v0.8

完整使用与开发说明：[工作台操作与开发指南](docs/工作台操作与开发指南.md)（2026年10月4日核对，包含 Codex 总管一期及尚未接通的能力边界）。

本机私人秘书：你是董事长。打开先看三份自动简报，再进入 Slack 式三栏指挥台。新项目 = 新模块，可拖拽改首页顺序。底部指令台随时向各部门下达，不必进部门页面。

## v0.8 新增 · 虚拟部门

- **一个目标，一条工作链**：在左侧「虚拟部门」输入一次目标，自动建立部门主管、主执行人、独立复核人、整合秘书四阶段。
- **强制独立复核**：执行人不能自审；不通过就带着意见退回返工，通过后才解锁最终整合。
- **真实模型执行**：每个阶段可调用「设置」中的当前模型路由，也可把 Cursor、Codex、WorkBuddy、ChatGPT 或人工产出回填到同一本机台账。
- **过程与成果同处**：阶段成果、复核意见、材料路径和最终稿都保存在 `data/store.json`，不用在 Agent 之间复制整段上下文。
- **视觉不换皮**：继续使用原来的紫色、暖白和深色主题；只借鉴 Paperclip 的组织与任务闭环。

## v0.5 新增 · 每日行程闭环

- **日 / 周 / 月视图**：同一份日程按日期锚点切换查看；周、月按实际日期分组，不复制第二份日程数据。
- **重点事项微信提醒**：有准确开始时间的重点事项，在开始前 12 小时经本机 PushPlus / Server酱配置发送一次；失败每 15 分钟重试。
- **材料路径直达**：每条行程可登记多条本机文件或文件夹路径，点击仅打开已登记且仍存在的路径。
- **日程报告**：各视图底部可生成日报、周报、月报草稿；只以本周期日程描述与复盘为事实底稿，再调用当前配置的本地或外接模型润色。

## v0.3.1 新增

- **决策台**（左侧一级导航「决策台」）：总控指标（在办/今日到期/受阻/风险灯）+ 风险雷达（逾期/受阻/超时自动汇总）+ 全项目决策表。
- **任务拆解**：决策台里把会议记录/原始素材拆成待办；支持「AI 拆解」。
- **模型路由**（设置页）：本地 Ollama 或任意 OpenAI 兼容在线接口，选通道决定走本地还是外部；密钥只存本机 store.json。
- **知识库**：记忆页升级为知识总览 + 教训 + 技能 + 提示词（能力资产）。
- **文件报送通道**：不会跑 HTTP 的 agent（豆包、天禧等）往 `data/dropbox/` 丢 JSON 即完成打卡，详见 `AGENTS.md`。

## 打开

需要本机已安装 Node.js。本仓库的运行代码只用 Node 内置模块，启动前不必 `npm install`。

双击 `start.bat`（本机）或 `start-lan.bat`（手机同 Wi-Fi 访问），或 `node server.js`，浏览器打开 [http://127.0.0.1:3780](http://127.0.0.1:3780)。第一次启动会生成 `data/store.json`。命令行可看 `node cli.js brief` 和 `node cli.js tasks`。

## 怎么用

1. 三份简报：经营 / 舰队 / 工作·学习·生活。看完或「今日不再弹出」。
2. **虚拟部门**：交代一个目标，按主管 → 执行 → 独立复核 → 整合推进；模型失败也不会丢目标。
3. **决策台**：一屏看清谁在干、干到哪、哪里有风险；会议记录贴进去拆待办。
4. 指挥舱：模块可新增、可拖排序；项目模块可指定**责任部门**。
5. 底部指令台：任何页面都能下达——选对象输入即可；点卡片上的「指挥」自动锁定对象；下达前有 Safe Mode 确认。
6. 全员通告：指令台对象选「📣 全员」，各 agent 须回执。
7. 指令追踪：舰队页每条指令看状态 待领 → 已收悉 → 执行中 → 完成。
8. 催报黄灯：任务 24h 无打卡、部门 48h 未汇报，自动亮黄灯。
9. 经营：日报、复盘、周指导、周报、月评估、月报、季度总结。
10. 知识库：AI 和你的沉淀（记忆/教训/技能/提示词）都可检索、可新增。
11. 其他 Agent 按 `AGENTS.md` 领取 inbox、推进状态并 checkpoint（HTTP 或文件报送均可）。

数据仍在 `data/store.json`（写入自动备份到 `data/backups/`）。这两处只留在本机，不进入 Git 历史。

## 不要提交

`.gitignore` 已排除运行时和私人材料。克隆后的空目录只保留 `data/` 与 `data/dropbox/`（含 `processed/`、`failed/`）占位；服务启动时会自己建台账和备份目录。

不要提交：

- `data/store.json`、`data/backups/`：唯一台账和备份。其中有任务内容，也可能有在线模型的 API key 和推送 token。
- `data/dropbox/` 里的真实报送、WorkBuddy 队列、Agent 结果、日志、Cursor CLI 安装目录，以及 `.workbuddy/`。
- `.env` 和任何 token、密钥。示例只看 `.env.example`，不要把真值写进去。
- 交接取证里的台账快照、对话原文、界面截图和源码副本：`docs/交接/evidence/当前台账.json`、`docs/交接/archive/`、`docs/交接/source-snapshot/`、`docs/交接/evidence/agent-results/`。交接说明正文仍在 `docs/交接/`。

红区信息（证件、原件价格、未脱敏照片）不要放进仓库，也不要 POST 进工作台。

## v0.3 变更（小迪接管后的第一版）

- 催报黄灯与同步时间提示（agent 卡片、任务卡片）。
- 模块迁移 v0.2 → v0.3：为项目模块补 `ownerAgentId`，为旧指令补状态字段；纯补默认值，不动既有数据。
