# 工作台类型 1（Type 1）

当前一级导航统一为四字：工作首页、项目中心、成员中心、每日行程、简报中心、我的关注、资产中心、学习成长、生活管理、系统设置。原工作报告入口改名为我的关注，旧链接仍打开原报告。原决策台归入工作首页；事业部和虚拟部门归入项目中心，保留各自记录。旧链接继续有效，数据不迁移。

二级侧栏顶部的纯图标按钮支持收起侧栏，收起后在一级导航顶部展开；记住本浏览器的宽屏偏好，窄屏使用可关闭抽屉。四角色卡片长说明与退回意见默认四行，点击各自的“展开详情”查看完整原文。详见 [界面精简规范](docs/SPEC-compact-layout.md)。
宽屏可拖动二级侧栏右边界调整宽度，刷新后保留，双击恢复默认；支持键盘调整。项目“…”菜单使用主题配套的清晰文字与背景。详见 [侧栏调宽与菜单规范](docs/SPEC-sidebar-resize-menu.md)。
Agent 状态区分台账登记与执行证据，刷新不伪写同步时间。资产中心新增技能工作室：从选定经验创建可编辑 Markdown 草稿，用户确认发布后保存实际文件；支持版本比较、回退草稿、固定输入测试与回执。第一版测试使用现有 Codex ChatGPT CLI，不改全局技能配置，WorkBuddy 保持暂停。知识检索与独立复盘继续沿用原边界，EvoFlow/Multica 外部接入仍预留。见 [技能工作室规范](docs/SPEC-skill-studio.md)、[三项目对比与后续方案](docs/PLAN-paperclip-led-workbench.md)、[职责整理规范](docs/SPEC-navigation-responsibilities.md) 与 [扩展接口约定](docs/扩展接口约定.md)。


这是个人本机 Agent 工作台的**第一型 / 基线**。GitHub 仓库名为 `workbench-type-1`。正在运行的程序仍叫「统筹工作台」；本机目录和地址 `http://127.0.0.1:3780` 不因仓库名而改变。

Type 1 维护**一份本机台账**。Cursor、Codex、WorkBuddy 以及其他 Agent 都读、写这一份进度，不另建平行进度表。台账包含虚拟部门工作链（主管 → 执行 → 独立复核 → 整合）、打卡（checkpoint）、指令（inbox）和项目群聊。接入约定见 [AGENTS.md](AGENTS.md)。

程序入口是 `server.js`：`node server.js`，或双击 `start.bat`。

## v0.10：归档、语言与使用说明

指挥舱的四张概况卡片支持同页筛选：正在推进的任务、今日行程、需关注的任务及台账有效成员。统计与明细使用相同口径，风险项显示受阻／逾期／未打卡原因，同一任务不重复计数。点击“显示全部模块”恢复原模块板；首次进入、刷新和重新进入默认显示完整模块，普通数据更新保留筛选。详见 [指挥舱筛选规范](docs/SPEC-overview-filters.md)。

**中国风 · 青墨** 是第四个可选主题，可在设置的“工作台主题”中应用。以宣纸与象牙色为底、松绿导航、青玉按钮及朱砂点缀，标题使用本机宋体／衬线字族，正文保持原有字体。主题选择刷新后保留，原有紫色、暖白、深色主题继续可用；无需外部图片或字体。设计参考及验收见 [中国风主题规范](docs/SPEC-guofeng-theme.md)。

每日行程新增独立复盘笔记：在已完成行程中保存复盘、生成可编辑摘要，确认后写入所选 Obsidian 仓库的 `工作台/行程复盘`。新增／修改行程的“建议”直接读取有效笔记并显示日期、原文及来源，历史或停用笔记不参与；该目录排除 VaultRAG，新功能的模型调用关闭 RAG。可通过“复盘笔记”整理历史复盘和调整适用状态。详见 [配置、使用与验收](docs/SPEC-agenda-review-notes.md)。

在草稿中回复待确认问题后，点击 **整合补充并更新摘要**，系统根据原始复盘与当前补充更新总结，把已回答内容纳入相应章节。对照或恢复整合前草稿，审阅后再确认保存新版本；旧文件保留。已保存的问答可通过 **载入已保存笔记** 继续整理。确认保存只写入当前文本，不会再调用模型；重新生成只读原始复盘，不能代替补充整合。

复盘笔记管理标明 **当前版本／已被替代** 以及是否参与建议。同一行程只使用最高版本且状态有效的笔记。可预览并 **移除旧版本**，或在保存摘要时勾选 **保存后移除旧版本**（默认关闭）；新文件成功保存并读回后才清理。移除文件保存在本目录 `.trash` 的恢复批次，可从管理页恢复，既不覆盖同名文件，也不替代当前较新版本。清理不会影响其他行程，整个目录继续排除 VaultRAG。

- 每个板块右上方的 **管理与归档** 提供单项、批量归档、关联预览、原文查看和恢复；设置入口可以管理全部集合。归档保留原状态和正文，不计为完成。
- 在办项目和任务归档后停止本工作台的后续领取、提醒和阶段推进；恢复后保持暂停，需选择 **继续所选**。原有复核暂停与 Start Writing 批准仍按原流程处理。已发出的外部调用不能保证强制中止；迟到成果保留于执行记录或项目历史，不解锁下一阶段。
- **设置 → 语言** 可选择中文或 English，刷新保持。系统界面和说明切换语言，项目、任务、简报、报告及路径保持原文。
- **设置 → 使用说明** 介绍十个入口及职责，并在本机展示完整逻辑图，支持折叠和放大。[直接打开说明](http://127.0.0.1:3780/#set/help)。文档原件：[中文逻辑图](docs/工作台全图-类型1.md)、[English logic map](docs/workbench-logic-type1.en.md)、[本次规范与验收](docs/SPEC-v0.10-archive-language-help.md)。
- 归档作用于工作台台账；各 Agent 自己的会话、外部定时任务和原始材料仍由原工具管理。

## v2 部门协作（第一切片）

新建项目时勾选「v2 部门协作」，或调用 `POST /api/departments/runs` 并传 `v2: true`。台账仍是这一条 `departmentRuns` 记录：上面叠一层董事长 → 主管 → 执行房间，四个阶段的领取、复核和整合继续走原来的接口。不勾选时行为与以前相同。

本地试一条（服务已在 `http://127.0.0.1:3780`）：

```bash
curl -s -X POST http://127.0.0.1:3780/api/departments/runs \
  -H 'Content-Type: application/json' \
  -d '{"goal":"试一条 v2 部门协作","context":"不外发","v2":true,"delivery":{"mode":"text"}}'
```

然后打开返回的项目房间，或 `GET /api/departments/runs/<runId>/org`。主管封印交接：

```bash
curl -s -X POST http://127.0.0.1:3780/api/departments/runs/<runId>/handoff \
  -H 'Content-Type: application/json' \
  -d '{"itemId":"<主管阶段 id>","summary":"方案已可交给执行房间","decisions":["先做最小切片"],"openQuestions":["验收命令是否只跑 npm test"]}'
```

同一输入第 4 次尝试会被阻断，房间上出现「同一输入已达三次」。细则见 [docs/SPEC-v2-department-collab.md](docs/SPEC-v2-department-collab.md)。

## v0.8 新增 · 虚拟部门

- **一个目标，一条工作链**：在左侧「虚拟部门」输入一次目标，自动建立部门主管、主执行人、独立复核人、整合秘书四阶段。
- **强制独立复核**：执行人不能自审；不通过就带着意见退回返工，通过后才解锁最终整合。
- **真实模型执行**：每个阶段可调用「设置」中的当前模型路由，也可把 Cursor、Codex、WorkBuddy、ChatGPT 或人工产出回填到同一本机台账。
- **过程与成果同处**：阶段成果、复核意见、材料路径和最终稿都保存在 `data/store.json`，不用在 Agent 之间复制整段上下文。
- **视觉不换皮**：继续使用原来的紫色、暖白和深色主题；只借鉴 Paperclip 的组织与任务闭环。

## v0.5 新增 · 每日行程闭环

- **日 / 周 / 月视图**：同一份日程按日期锚点切换查看；周、月按实际日期分组，不复制第二份日程数据。
- **重点事项微信提醒**：有准确开始时间的重点事项，在开始前 12 小时经本机 PushPlus / Server酱配置发送一次；失败每 15 分钟重试。

- **日程报告**：各视图底部可生成日报、周报、月报草稿；只以本周期日程描述与复盘为事实底稿，再调用当前配置的本地或外接模型润色。

## 打开

需要本机已安装 Node.js。首次获取项目先运行 `npm ci`，再运行 `npm run build:assets` 生成本地语言和图形资源，之后启动服务。`npm start` 会先重建资源；已有资源时也可以直接 `node server.js` 或双击启动脚本。界面运行时不依赖远程 CDN。

开发验证：`npm test`（原有回归、归档 API/异步结果、翻译覆盖）、`npm run test:agents`（模拟 Agent 领取契约），以及 `npm run test:ui`（需要本机 Microsoft Edge，使用独立临时台账，不调用真实 Agent）。可选 `PLAYWRIGHT_MODULE` 指向现有 Playwright。新增依赖版本锁定于 package-lock.json，本地图形资源附带对应许可声明。

更新已在运行的服务后，需要重启原服务使后台规则生效；`start.bat` 检测到已有服务时只打开页面。

双击 `start.bat`（本机）或 `start-lan.bat`（手机同 Wi-Fi 访问），或 `node server.js`，浏览器打开 [http://127.0.0.1:3780](http://127.0.0.1:3780)。第一次启动会生成 `data/store.json`。命令行可看 `node cli.js brief` 和 `node cli.js tasks`。

## 怎么用

1. 三份简报：经营 / 舰队 / 工作·学习·生活。看完或「今日不再弹出」。
2. **虚拟部门**：交代一个目标，按主管 → 执行 → 独立复核 → 整合推进；模型失败也不会丢目标。
3. **决策台**：一屏看清谁在干、干到哪、哪里有风险；会议记录贴进去拆待办。
4. 指挥舱：模块可新增、可拖排序；项目模块可指定**责任部门**。
5. 底部指令台：任何页面都能下达——选对象输入即可；点卡片上的「指挥」自动锁定对象；下达前有 Safe Mode 确认。
6. 全员通告：指令台对象选「📣 全员」，各 agent 须回执。
7. 指令追踪：舰队页每条指令看状态 待领 → 已收悉 → 执行中 → 完成。
8. 催报黄灯：任务 24h 无打卡、部门 48h 未汇报，自动亮黄灯。
9. 经营：日报、复盘、周指导、周报、月评估、月报、季度总结。
10. 知识库：AI 和你的沉淀（记忆/教训/技能/提示词）都可检索、可新增。
11. 其他 Agent 按 `AGENTS.md` 领取 inbox、推进状态并 checkpoint（HTTP 或文件报送均可）。

数据仍在 `data/store.json`（写入自动备份到 `data/backups/`）。这两处只留在本机，不进入 Git 历史。

## 不要提交

`.gitignore` 已排除运行时和私人材料。克隆后的空目录只保留 `data/` 与 `data/dropbox/`（含 `processed/`、`failed/`）占位；服务启动时会自己建台账和备份目录。

不要提交：

- `data/store.json`、`data/backups/`：唯一台账和备份。其中有任务内容，也可能有在线模型的 API key 和推送 token。
- `data/dropbox/` 里的真实报送、WorkBuddy 队列、Agent 结果、日志、Cursor CLI 安装目录，以及 `.workbuddy/`。
- `.env` 和任何 token、密钥。示例只看 `.env.example`，不要把真值写进去。
- 交接取证里的台账快照、对话原文、界面截图和源码副本：`docs/交接/evidence/当前台账.json`、`docs/交接/archive/`、`docs/交接/source-snapshot/`、`docs/交接/evidence/agent-results/`。交接说明正文仍在 `docs/交接/`。

红区信息（证件、原件价格、未脱敏照片）不要放进仓库，也不要 POST 进工作台。

### 文件交付与验收

新建项目选择正文或 Word 文件交付。Word 项目由工作台转换执行正文，保留源版本并校验文件读回；独立复核和整合完成后才显示文件交付通过。项目房间提供真实路径、大小、SHA-256、源版本与打开入口。文件被删除、修改或源正文改变，核验失效。历史项目保留原阶段结论，可补充文件交付要求；旧成果不覆盖。普通群聊继续只讨论，桥接 JSON 不作为业务文件。文件操作仅开放本机回环访问。

接口：`GET /api/departments/runs/:id/delivery`；`POST .../delivery/configure`、`generate`、`review`、`retry`、`open`。复核提交必须携带本批文件快照，执行人与复核人不得相同。`review` 是实际文件复核回填，不能用自动构造的空通过意见替代独立检查。

DOCX 自动导出适用于 Markdown 正文、列表、代码、表格和链接。源中包含未支持的图片或 HTML 时会明确阻塞，不静默丢弃。真实版式验收需实际 Word/渲染检查，自动文本读回及模拟测试不代替该验收。
